# TunBox 0.5.3：后台刷新优化

基线：已合并上游 main 0.5.2 的 76398743639908d3fe9425fc279628e5e13faed1。
原 Draft PR #5 已更新，GitHub 确认为可合并。本文对应独立分支 perf/background-refresh-0.5.3。

## 改动

- 速率统计：应用前台每 2 秒，后台每 10 秒；回前台立即补一次读取。无 UI 的启动默认走后台频率。
- 首页被隐藏、切换页签或进入子页后，停止图表和连接预览定时器；连接管理页退出或退后台后也停止轮询。延迟初始化和晚到结果不能重启隐藏页面。
- 主页时长始终按原始 startedAt 计算，恢复显示不重置会话，也不补造历史图点。
- 流量统计、连接列表及实际出口节点共享一次在途 controller 查询，成功结果在 500 毫秒内复用；失败不缓存。切换 endpoint、重置统计、重载配置和关闭连接后失效缓存。
- 统计按真实采样时间差计算；旧会话、旧轮询代次的结果不能覆盖新数据。
- 桌面信息卡刷新由 3 秒调整到 10 秒；原有 3 秒状态对账保持原样。
- 完全相同的通知数据不重复发布，通知任务重新挂载时清除去重状态。
- 应用版本 0.5.3，versionCode 517（上游为 516，避免安装降级）。

音频保活默认值、30 秒自检、Protect 通道、VPN 扩展租约和故障恢复判据保持原样。广告规则沿用本轮已确认的手动下载策略。瑞幸开屏广告不在本次范围内。

## 验证

- 新增 verify-power-refresh-runtime.mjs：17 项通过，执行实际 API/编排器/页面方法，替换系统边界与时钟。覆盖查询合并、缓存过期和失效、端点竞态、真实时间差、前后台次数、计时连续、隐藏页面和通知去重。
- 受影响的 16 组回归通过，包括会话恢复、音频保活、广告规则、规则页、订阅转换、DNS/配置、应用分流和网站分流。Profile 合并脚本的真实 mihomo CLI 项因本机无对应二进制而跳过，不能当作内核配置验收。
- 本机 SDK 26.0.0.105 / Hvigor 6.26.8 / Node 24.14.1 / JBR 25.0.2 调试 HAP 构建成功，串行构建，复用现有工具缓存。
- 包内版本、ARM64 ELF 依赖、ZIP CRC、随包数据库和构建输入哈希另由交付校验记录验证。

固定时钟测试中，后台每分钟例行统计请求为 6 次，前台为 30 次。这是例行统计请求数量减少 80%，不是电量消耗减少 80%。

## 真机复测

本版本尚未完成优化后的真机锁屏与耗电验收。应先验证切换页面、退后台和恢复时计时连续，用户停止后不会被旧回调拉回；再检查锁屏 30 分钟、2 小时后的代理可用性。

耗电比较以本次合并版本为基线，与优化版使用相同订阅、节点、网络、签名和音频关闭设置，按 A/B/B/A 各 30 分钟采样。记录全部应用进程 CPU、整机电量和温度，不能将 CPU 差值直接换算为应用 mAh。
