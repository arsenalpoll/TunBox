## 0. 为什么要重写（取证）

真机症状：**「同一节点在隧道里能用、在测速核里失败」**。

结构根因不是玄学，是**同一件事有 2~5 份真源**：

| 分叉点 | 旧实现的两个真源 | 后果 |
|---|---|---|
| 配置 | 隧道 `ConnectionOrchestrator.connect()` 与测速核 `launchTestCore()` 各自 `ClashConfigGenerator.generate()`，入参不同（useSmart / ruleProviderReady / selectedNode / proxyHosts / useGeoip / tun.enable / secret / 端口） | 隧道 pin 住的节点在测速核里没 pin 住；隧道启用的去广告规则集在测速核里没启用 → 「同一个节点两个结论」 |
| 解析 | `ProxyNode.fromUri` + `ModernUriCodec.parse*`（旧）与 `commons/subscription/UriNodeParser.ts`（新）并存 | 同一份 URI 两套「缺参」判断：旧的把缺凭据节点塞进内核（节点存在但握手失败 = 测速全败的真凶之一） |
| 失败分类 | `LatencyState.LatencyPolicy` 四张表 / `ClashApiService.LatencyFailKind` / `LatencyProbe.LatencyProbeKind` / `LatencyStore.describe` / `theme/*Tokens` 的渲染包装 | 同一类失败在 5 个文件里各写一遍文案与集合 → 改一处、别处还是旧话术 |
| 结论落盘 | `AppSettings.nodeSortSnapshot` 整单 JSON（多个写者）vs `SettingsService` 分片（单一写者） | 后写者把先写者的字段盖回旧值（审计 F2）；「一次连接失败」被写成 latency=-1 → 真实测速延迟被抹掉，冷启动渲染成假的红「超时」 |
| 端口 | 测速核端口探测写回共享的 `this.apiPort/mixedPort/dnsPort` | YAML 里写的端口与客户端 `setEndpoint` 用的端口对不上（审计 F1，高危） |

**FlClash 只有一份配置** —— 结构上没有这类分叉。重写的目标不是「改得更好」，是**把每一类事实收敛到唯一真源**。

## 2. 旧实现逐文件清单

> 记号：**[已删]** = 已从运行时路径移除；**[待删]** = 还在，需按前置条件清理。
> 「为什么删」一栏写的是**结构性理由**（不是「代码不好看」）。

### 2.1 订阅解析（IR 层）

#### [待删] `commons/models/ProxyNode.ets` — `ProxyNode.fromUri` + `ModernUriCodec.parse*` + `SsrCodec.parse*`

- **为什么删**：同一份 URI 有两套解析器，两套对「缺参数 / 保真」的判断不一致 ——
  旧解析器把缺凭据的节点照样塞进内核（节点在代理表里、握手必失败 = 「测速全败」的真凶之一），
  且旧解析器按协议各自散落字段（`clientFingerprint` 与 `certFingerprint` 曾经共用一个槽位，
  hysteria2 节点因此被写成非法 pin）。
- **被谁取代**：`commons/subscription/UriNodeParser.ets`（`parse(uri) → ParsedNode | error`）
  + `commons/subscription/ProtocolParamTable.ets`（每协议一张参数表：键/类型/必填/敏感/落到 mihomo 哪个字段）
  + `commons/subscription/YamlNodeAdapter.ets`（规范键映射回旧 `ProxyNode` 字段，使生成器不用改）
  + `commons/subscription/NodeUsability.ets`（缺参 ⇒ unusable + 原因，**不伪装成「网络不可达」**）。
- **前置条件**：
  1. yaml-sub 的 task-9 落地：`SubscriptionService` / `SubscriptionParser` 的导入链路改走 `UriNodeParser`；
  2. 闸门 `scripts/verify-sub-parse-fidelity.mjs` 绿（URI 保真 + 缺参不进代理表/不进测速集合）；
  3. `pages/NodeEditPage.ets` 的**手动单条导入**改走新解析器（或明确保留 `fromUri` 并在闸门里豁免 `LP12`）；
  4. `ModernUriCodec.parse*` 无调用方（闸门 LP11/LP12 绿）。
- **注意**：`ProxyNode` **这个数据类本身不删** —— 它仍是生成器的输入模型；删的只是「解析入口」。

#### [待删] `commons/services/SubscriptionService.ets` — `sealPlaintext` / `nodeSetFingerprint` 的旧职责

- **为什么删**：`sealPlaintext`（导入后清内存明文）与「回填」被编排器在 3 处各自 `try/catch` 调，
  行为不一致（有的路径没回填 → 节点缺凭据整条被生成器跳过 → 节点不在内核代理表）；
  `nodeSetFingerprint` 是**节点集合**的旧指纹，与新的 `RuntimeProfile.profileFingerprint()`
  （规范化文本 SHA-256，能回答「这份配置比上次变了什么」）口径不同，两个指纹会给出不同答案。
- **被谁取代**：`commons/subscription/RuntimeProfile.ets` 的 `profileFingerprint()`；
  凭据封存/回填收敛到**一处**（生成配置之前，见 2.4）。
- **前置条件**：task-9 落地 + `verify-sub-parse-fidelity.mjs` 绿 + 编排器回填点收敛为 1（LP13）。

#### [已改] `commons/services/ClashConfigGenerator.ets` — 测速地址的旧规则（2026-10-20 A12c）

- **为什么改**：生成器里有**两份**测速地址实现 ——
  ① smart 组直接读用户的测速设置（非法值不校验，能写进 YAML）；
  ② `safeGroupUrl()` 自带一套「http(s) 前缀判定 + 2048 长度 + gstatic 兜底」。
  与 `LatencyTestUrl.effective()`（真源）三份口径 ⇒ 同一个地址三种话术（审计 F12）。
- **改成什么**：
  - 新增 `import { LatencyTestUrl } from '../latency/LatencyTestUrl'`（零 import ⇒ 无循环依赖）；

  - smart 组 url 改由 `LatencyTestUrl.effective()` 决定；
  - `safeGroupUrl()` 只保留 **YAML 安全**（不含破坏字符）与转义，合法性/默认值全部交给真源。
- **前置条件**：无（已完成）。闸门 `verify-latency-core-v2.mjs` A12c ✅（65/0）、
  指纹闸门 ✅（`a51e7dd946dcb136` → `4f1c772e9662ca2c`，原因见 `docs/latency-redesign.md` 第八节）。
- **行为变化（需要知道）**：smart 组的 `url` 现在**总是显式写出**（空值 → 默认 https gstatic，
  与内核默认同值）；订阅自己声明的组 url **仍原样保留**；历史 http 默认值按真源口径升级为 https。

### 2.3 测速路径

### 2.4 编排器（`commons/services/ConnectionOrchestrator.ets`）里的重复逻辑

> 注意：本轮**不删任何文件**，也不改编排器。以下是「要收敛成什么」的清单。

#### [待收敛] 凭据回填 3 处调用（`hydrateNodeCredentials`）

- **现状**：`hydrateNodeCredentials(subs)` 在编排器里被调 **3 次**（生成配置前 / 重连前 / 热重载前），
  每次各自 `try/catch` + 各自日志 —— 其中一条路径若没回填，节点就因「缺凭据」被生成器**整条跳过**，
  表现为「节点列表有它、内核里没有」。
- **收敛成**：在 `RuntimeConfigBuilder.buildRuntimeConfig()` 之前**唯一一次**回填（或由编排器在
  进入生成流程的统一入口做一次），其余 2 处删除。
- **前置条件**：task-9 的凭据迁移链路落地 + 闸门 LP13（回填调用点 = 1）绿。

#### [待收敛] 旧 fingerprint

- **现状**：`SubscriptionService.nodeSetFingerprint(nodes)`（节点集合指纹，用于「通知去重」）
  与新 `RuntimeProfile.profileFingerprint()`（规范化文本 SHA-256，能回答「这份配置比上次变了什么」）
  两套口径并存。
- **收敛成**：统一用 `profileFingerprint()`；`nodeSetFingerprint` 若只用于通知去重，删除或改用新指纹。
- **前置条件**：task-9 落地（IR 能稳定产出 profile）。

#### [已收敛] 端口写回

- **现状（旧）**：测速核端口探测写回 `this.apiPort/mixedPort/dnsPort`（审计 F1）。
- **收敛成**：`RuntimeConfigProfile` 显式端口入参 + `RuntimeConfigResult` 回传，
  测速核用自己探测的端口，**不回写**共享字段。闸门 `verify-config-single-source.mjs` A4/B3 ✅。
