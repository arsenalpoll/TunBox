# 启动按钮轨道元素「永不重叠 + 十字对称」（2026-10-18）

## 用户诉求（两轮）

1. > 主页的代理启动按钮，现在外围两个圈上面各有一个球和一条线在四周转动，
   > 经常会转动的重叠在一起，我希望转动的动画永远不要重叠，全部分开。
2. > 改成对称吧，长条的长度改的跟现在长的那一根一样长，两个球也对称，
   > 形成一个十字，然后就保持匀速转动。

## 根因（为什么「调参数」救不了）

`CelestialPowerOrb` 里四个转动元素各有**不同角速度**：

| 元素 | 旧角度公式 |
|---|---|
| 蓝弧 | `ARC1_BASE + spinDeg`（1.0×） |
| 绿弧 | `ARC2_BASE + spinDeg * 0.55`（0.55×） |
| 外圈球 | `-90 + spinDeg`（1.0×） |
| 内圈球 | `30 - spinDeg * 0.8`（**反向** 0.8×） |

相对角度随 `spinDeg` 线性漂移 → 无论初始相位怎么调，都会在某一时刻重合，
之后周期复现。这不是参数没调好，而是「不同速」这件事本身保证不了不相交。

## 修复

1. **统一角速度**：四条元素 `speedFactor` 全为 1，共用同一轨道相位 `spinDeg`，
   彼此只保留固定角度偏移 → 任意两元素角间距**恒定**，永不重叠。
2. **十字对称布局**（用户第二轮要求）：
   - 两球同在外轨 `r = 140`，相隔 180°（上 / 下）；
   - 两条长条同在轨环 `r = 130`，**等长 42°**（取旧实现较长那根的长度），相隔 180°（右 / 左）；
   - 球轴与长条轴正交（相差 90°）→ 任意相位都保持十字形态。
3. **几何抽成纯函数模块** `components/CelestialOrbLayout.ets`（零 `@kit` 依赖），
   让回归脚本能真跑几何而不是读源码。

## 回归（`scripts/verify-orb-separation.mjs`，真跑几何）**8/8**

```
PASS 四个转动元素齐全（外圈球 / 蓝弧 / 内圈球 / 绿弧）
PASS 所有元素同速（speedFactor 全为 1）
     实测最小间距 = 96.9vp        ← 扫整圈 360°、步长 1° 得到的最小视觉间距
PASS 任意相位下两两视觉间距 ≥ 20vp
PASS 间距是常数（同速 → 不随相位变化）
PASS 两条长条等长（都是 42°，十字对称）
PASS 十字对称：两球同轨且相隔 180°，两长条同轨且相隔 180°
     最大角空隙 = 90°
PASS 沿圆周分布均衡（不会挤在一侧）
     0.55 倍速时最小间距 = -4.5vp（<20，判为重叠）
PASS 反向验证：把绿弧改回 0.55 倍速会被判出重叠（守卫生效）
```

最后一条是**守卫自检**：故意把绿弧改回旧的 0.55 倍速，脚本必须判出重叠 —— 证明
这个测试真能抓住「不同速」这类回归，而不是恒真。

视觉外延：球光晕半径 11vp、弧线半宽 2.25vp，合计约 13vp；实测最小间距 96.9vp，
余量约 7 倍。

## 真机验证

装包后连拍两帧（间隔 5s）：两球始终在竖直轴、两条等长长条始终在水平轴，
四者相隔 90°，转动中不重叠。截图：`orb_cross_1.jpeg` / `orb_cross_2.jpeg`。

## 追加：球必须落在长条中线上（同日第三轮反馈）

**用户原话**：> 小球的位置要再横线的中间，要保证都在十字架对应的位置，完全对称，
> 现在小球没有完全在十字中线上。

两处几何偏差，前两轮都没处理干净：

1. **长条没有关于自己的轴居中**。第一版长条是 `0°→42°` / `180°→222°`，
   起点压在水平轴上、末端甩到 42°，长条的**几何中心**其实在 21°/201°；
   而球在 90°/270° —— 球相对「十字中线」偏了 21°，看起来就是不在中线上。
   → 改为 `-21°→21°` / `159°→201°`，中心线严格落在 0°/180°。
2. **球与长条不同半径**。球在 r=140（外圈点阵轨道）、长条在 r=130（轨环），
   两条「臂」落在不同圆周上，一长一短，视觉上球像贴在外圈虚线上跑。
   → 四者统一 `r = 130`。

现在的形态：球 90°/270°、长条中线 0°/180°，两轴严格正交，四者同半径、两两相隔 90°。
